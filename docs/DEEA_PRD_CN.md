# DEEA 产品需求文档（中文）v0.1

状态：供评审的设计草案｜2026-09-23｜适用范围：单浏览器、单写作者、英语议论文 Demo

## 1. 产品概述与问题

DEEA（Academic English Evolution Agent）跟踪同一写作者多篇议论文中的词汇选择，帮助教师和学习者发现反复依赖的表达，设定可操作的拓展目标，并查看后续写作中是否出现即时变化、初步维持或可能回归。

教师能记得学生“常用 important”，却难以逐篇回查次数与教学后变化；学习者听到“丰富词汇”也难以知道下一步练什么。DEEA 的核心体验是让一条教学目标连上过去作文、后续作文和原文证据，而非给某篇文章打分。

## 2. 目标用户与场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 一对一、IELTS/TOEFL、学校英语教师 | 查看同一学生的多篇议论文，挑选值得训练的表达 | 能核查重复依据，人工设置目标，回看训练后的变化。 |
| IELTS/TOEFL 备考者、大学英语写作者 | 反复练习议论文并保存自己的作文 | 知道目前优先拓展什么、下一篇做什么、后续是否保持。 |

首版**同一浏览器对应一名写作者**，教师和学习者共用界面。无学生身份认证、多作者数据隔离或跨设备同步。并非完整写作质量评价工具。

## 3. 产品目标与验收标准

**目标**：让一名用户走通“保存数篇同类作文 → 查看待核查的重复表达 → 人工选定并设置词汇目标 → 保存后续作文 → 查看 +1/+3/+5 观察证据”的流程。

| 验收场景 | 可验收行为 |
| --- | --- |
| 保留写作输入 | 可以继续填写标题、写作日期、题目、原文，分析后保存；旧记录仍可读。 |
| 文体隔离 | 未确认的旧作文、非议论文不得进入跨篇比较；被排除后趋势和目标窗口更新。 |
| 候选诚实性 | 词出现 ≥3 次且位于示例形容词名单和 COCA 搜索范围时标“待核查”；不凭 lemma 的词性列表声称该 token 必为形容词。 |
| 长期证据 | 可看某词出现于哪些作文、各篇次数、连续出现情况，并跳转原文。 |
| 目标与观察 | 可人工创建/编辑目标；目标起点明确；+1/+3/+5 的证据对应正确后续作文；样本不足不作维持结论。 |
| 边界情形 | 删除作文、同日作文、未知语义分母、目标锚点失效、数据清空都有明确提示或安全回退。 |

本轮文档尚未实现上述新增行为；验收标准用于后续开发。

## 4. MVP 范围

**包含**：议论文输入与历史；单篇 lemma 次数和 COCA 参考；少量人工配置的形容词示例组；单篇 ≥3 次候选；跨篇出现证据；人工目标及教学提示；Growth 首页；+1/+3/+5 观察窗口；原文可追溯性。

**后续**：自动上下文词性与语义功能判别、完整组库、AWL/UWL 基准、AI 建议、短语搭配、写作评分、语法批改、账号和班级后台、多文体比较。COCA Top 5K 仅是候选搜索范围和频率背景，低频不等于高级，高频不等于低水平。AWL 是后续可考虑的学术词汇维度。

## 5. 核心流程

1. 用户在 New essay 写英语议论文并保存。旧作文先由用户确认文体与纳入资格。
2. 单篇结果展示 3–5 个优先核查的候选及次数、原文语境；仍允许展开完整 lemma 表。候选不足时据实显示。
3. Growth 汇总同文体多篇中的复现情况；用户从候选进入原文并选择一个可训练的词。
4. 用户设定目标词、教学说明、适用语境、可选的替代表达，并把某篇作文作为目标起点。
5. 后续每保存一篇合格议论文，目标详情更新观察窗口，展示逐篇证据；+1 为即时响应，+3 为初步维持，+5 为持续趋势检查。这里的数字是**产品假设**，未证明为学习阈值。
6. 若没有足够语义机会或话题不相近，只报告可见计数和待核查变化；不自动宣称“掌握”或“退步”。

## 7. 检测规则与数据定义（待验证）

| 规则 | v0.1 定义 | 防误判条件 |
| --- | --- | --- |
| 合格作文 | 同一浏览器作者、已确认为英语议论文、原文非空；按写作日期、创建时间、ID 稳定排序。 | 旧数据默认“待确认”；题目可能改变词汇使用机会。 |
| 单篇候选 | 示例形容词名单中的 lemma，COCA Top 5K 可检索，单篇计数 ≥3。 | 现有分析无 token 词性标注；标“候选”，人工核查。 |
| 意群集中度 | 人工核查的同组使用机会中，目标表达次数 ÷ 同组总机会数；>50% 为集中候选。 | 分母为 0 或未标注时“未评估”，不把全部词数作为分母。 |
| 跨篇复现 | 展示出现篇数/纳入篇数、总次数、按时间逐篇次数和连续出现篇数。 | 不把重复本身等同于过度依赖，尤其在提示词要求该概念时。 |
| 基线 | 优先参考目标前至少三篇合格作文；不足时仍可存目标，但标“基线有限”。 | 三篇为产品提案，需用教师反馈和真实样例校准。 |
| 后续观察 | 目标锚点之后第 1、3、5 篇合格作文对应即时、初步、持续观察节点。 | 后补作文、删除、排除都会重排窗口；状态须重新计算。 |
| 状态表达 | 待观察、即时变化、初步维持、持续趋势、可能回归。 | 数值方向只是线索；“改善/回归”须有语义机会、语境和人工复核，否则使用“次数变化待核查”。 |

不要把跨篇 `rate per 100 words` 设为主指标；可在详细数据中辅助比较篇幅不同的作文。COCA coverage 表示当前分析 token 在所用有限词表中的命中比例，不是语言水平分数。既有 lemma 词形还原有限，对歧义形式可能误归类。

## 8. 存储与数据变化

现有 `EssayRecord` 在 `localStorage` 中保存原文与时间，分析结果按当前算法重新计算。后续应保留旧记录可读，新增文体纳入标记、目标记录、目标锚点作文 ID、人工核查和教学说明；自动计算字段与人工内容分开存，明确数据版本。删除/排除作文后重算跨篇指标。目标锚点若失效，标待重新锚定。用户始终看到“仅存本浏览器”的提示。

## 9. 指标与观察

Demo 优先用本地测试数据核对：用户能否找到重复依据、能否创建目标、能否看到后续文章与状态证据。未来如设计埋点，只采集验证闭环所需的 `essay_analyzed`、`target_created`、`growth_viewed` 和各观察窗口完成事件等；属性不含作文原文。当前没有联网埋点服务，不在本轮文档工作中接入。

## 10. 风险、依赖与后续迭代

- 词性歧义与简单词形还原影响自动候选；先用小组示例和人工复核，避免确定性诊断。
- 写作题目不同会改变表达机会；展示原题与原文，不能只据 raw count 判好坏。
- 单浏览器数据易丢失，Demo 页面需始终说明；正式教学使用再考虑导出和账号同步。
- +3/+5 状态及阈值需要教师评审与样例验证；先展示透明证据，再决定是否自动给出定性标签。
- 工程实现前需定稿规则说明和验证案例，尤其目标序列与删除后的重算。
