# DEEA Gap Analysis v0.1

状态：产品设计草案｜核对基线：`main`，2026-09-23

## 目的与核对范围

目标是验证“发现跨篇表达依赖候选 → 设置拓展目标 → 继续写议论文 → 观察变化与回归”的闭环。本文件依据仓库中的 `README.md`、`src/App.tsx`、`src/analysis/*`、`src/storage/essayRepository.ts` 和 `src/types/*` 核对现状；描述的是代码能力，并非真实学生数据的验证结果。

| 能力 | 当前实现与证据 | 与 Demo 的差距 / 处理 |
| --- | --- | --- |
| 作文输入 | `App.tsx` 有标题、日期、可选题目、正文、分析和保存；`essayRepository.ts` 验证必填项。 | **复用并修改**：保留正文输入；增加议论文任务类型提示与范围控制。旧作文没有文体标签，不能自动认定为议论文。 |
| 作文历史 | `EssayRecord` 存原文、写作日期及时间戳；History 可查看、删除并按当前算法重算单篇分析。 | **复用并扩展**：新增可纳入比较的议论文标记、跨篇序列与目标关联；删除后重算相关观察窗口。 |
| 单篇词汇分析 | `analyzeEssay.ts` 做分词、轻量词形还原、停用词过滤、lemma 次数和 COCA 覆盖；`coca.ts` 按 lemma 汇总不同词性并派生排名。 | **复用底层、修改呈现**：优先显示少量候选词及可核查的原句，完整表下沉；每 100 词频率仅作辅助，不作为“表达依赖”证明。 |
| 形容词候选 | 数据含词性列表，但 `analyzeEssay.ts` 不做上下文词性标注；同一个 lemma 可同时属于不同词性。 | **新增保守候选机制**：少量人工选定的形容词及语义组；出现 ≥3 次仅触发“待核查”。不能声称每次 token 都是形容词。 |
| 意群集中度 | 没有语义功能标注、同类表达机会计数。 | **示例组 + 人工复核**：只有经过该组语境核对的机会数才能计算 `目标词次数 / 同组机会数 > 50%`；无数据时显示“未评估”，不填 0%。 |
| 跨篇复现 | History 对每篇独立重新分析；无聚合、连续篇数、基线或趋势。 | **新增**：按同一写作者、同文体及确定顺序统计“出现于几篇 / 总次数 / 连续几篇”，并展示每篇次数；缺少语义机会时不下“过度依赖”结论。 |
| 词汇目标 | 无目标、替代表达、教师调整、起点或状态模型。 | **新增**：目标与触发它的历史作文 ID 关联，允许人工编辑例词及适用语境；明确目标开始点。 |
| 后续观察 | 无 +1/+3/+5 窗口，无改善或回归判断。 | **新增**：以目标建立后的合格作文序列观察；+1 只报告即时变化，+3/+5 为产品观察窗口，尚非学习科学阈值；样本不足标“待观察”。 |
| Growth | 导航只有 New essay / History，首页默认为 New essay。 | **新增**：Growth 作为入口概览；空数据引导写第一篇，有数据展示目标、证据与后续进展。History 保留原文证据。 |
| 多用户与持久性 | `localStorage` 仅当前浏览器，没有账号或作者 ID。 | **范围约束**：一次 Demo 只针对这个浏览器中的一名写作者；清理浏览器数据会丢失记录，不能用于班级或跨设备比较。 |
| 验证基础 | 有分析、存储和 UI 的单元/交互测试。 | **新增针对规则的验证**：不同文体排除、同日排序、目标边界、删除重算、词性歧义、无语义分母、+1/+3/+5 不夸大结论。 |

## 关键产品差距

1. **从记录到追踪**：已有原文和日期，尚无同一写作者跨篇的比较模型。
2. **从次数到教学判断**：出现 ≥3 次、COCA Top 5K 均只用于筛选；没有语义机会分母与语境核对时只能叫“候选”。
3. **从反馈到观察**：缺少目标开始点、后续作文序列和可追溯的状态证据。
4. **从数据表到行动**：现有结果以 COCA 表格为主，尚未提供 3–5 个待关注词及下一步行动。

## 可复用与改造顺序

1. 复用 `EssayRepository`、`EssayRecord`、`analyzeEssay` 和 COCA 数据读取；先给旧记录加入**显式纳入/排除**的议论文判断，不改写旧文本。
2. 建立独立的候选、语义组、目标、观察结果模型；把分析版本与人工确认信息分开保存。重算不能覆盖人工决定。
3. 展示单篇候选与证据，再做跨篇视图，最后加目标及后续窗口；每一步都能从原句追溯。
4. 完成 Growth 页面后调整入口；保留 New essay 的显眼入口和 History 的原文查看能力。

## Demo 暂不做

自动写作评分、语法批改、AI 全文改写、完整形容词词性标注、自动语义分组、AWL/UWL 正式基准、短语搭配分析、班级后台、登录同步、多文体趋势。COCA 频率与 AWL 资格均不应直接等同于“词高级”或“写得好”。

## 待验证的产品假设

- 至少三篇同类作文作为初始基线更易解释；这是设计提案，非研究支持的统一门槛。
- +1/+3/+5 篇可帮助教师区分即时响应与后续维持；状态判定与变化阈值须经样例和教师复核校准。
- 少量人工语义组足以演示闭环；若无法给出语义机会分母，界面只展示重复证据。
