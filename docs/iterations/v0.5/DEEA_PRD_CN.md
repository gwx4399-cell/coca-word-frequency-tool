# DEEA v0.5：从原句到后续写作证据

日期：2026-11-03 至 2026-11-04（Asia/Taipei）。状态：分支已实现；[草稿 PR #10](https://github.com/gwx4399-cell/coca-word-frequency-tool/pull/10)，尚未合并或发布。基于 v0.4。

## 问题与决定

教师需要把多篇作文整理到同一学生、同类任务下，确定一个可教目标，再核查修改稿及新的独立写作。仅统计重复不能说明需要修改，更不能证明学会了。用户目前没有教师参与试用，本版先完成可操作流程和虚构练习，不将代理走查包装成真实教学实验。

[LexTutor RANGE](https://www.lextutor.ca/range/) 已支持多文本分布；[Write & Improve Class View](https://writeandimprove.com/classview) 已支持版本和教学管理；[Quill](https://www.quill.org/faq) 展示了诊断、练习和复查的衔接。本版的设计假设是让证据、教师决定与后续任务更容易连在一起，不宣称这些功能独创，也未证明节省时间或促进学习。

## 已实现流程与验收

| 环节 | 行为与验收 |
| --- | --- |
| 分组 | 作文带学生编号/昵称、文体、任务名称。旧作文保持未分组，不猜测作者。同名学生需使用不同编号。历史可查看全部或某学生；跨篇必须选定学生和文体。 |
| 可比稿件 | 比较每个任务的最新稿或原稿，可取消具体任务。相同任务名称视为同一任务；没有名称时按修改关系划分。最近三篇提示也使用这个范围。逐篇证据显示原始词数、次数和每百词频率，均非质量分。 |
| 版本 | 从历史创建修改稿，继承学生、文体、任务，保留父稿和原文。可对照上一稿与当前稿。新任务由使用者明确标为独立写作；已导入原稿也能在分组编辑中调整任务类型。独立性未经工具鉴定。 |
| 教学判断 | 选择一条原句，标记保留、需要具体化、搭配/语气待核查或归并有误，填写理由。保存后可以编辑。人工标记不改动分析算法或原文。 |
| 学习目标 | 判断可附带具体目标与练习方式。每位学生通常同时最多两个活跃目标；可归档/恢复，保留证据。两个是控制工作量的产品约束，未经教学验证。导入冲突可能保留更多目标，界面提示人工核对并归档。 |
| 后续核查 | 从同一学生后续修改稿或独立任务中选原句，记录状态、依据与可选学生反思。区分“修改稿中完成”“新任务中有证据”“仍需练习”“没有适用机会”。最后一种无需强行选择原句，但必须说明理由。不会自动评分、自动完成目标或把词语缺席当进步。 |
| 交换材料 | 多个 UTF-8 TXT 按学生批量预览/导入；每文件一篇任务原稿、文件名作任务名、共用所填日期。导出单个任务或当前活跃目标的 HTML 反馈单，浏览器可打印/保存 PDF，长内容会分页。 |
| 备份 | v2 包含全部学生、版本、原文、判断、目标和核查；仍可导入 v1。确认前预览，重复不新增；冲突文字/判断保留两份并提示，不覆盖。失去证据关联的删除或分组操作被阻止。 |

## 不依赖真实教师的试用入口

“批量导入与模拟练习”提供三组虚构短文：基础表达、表达拓展、语义与语气。每组原稿、修改稿、新任务各一篇，共九篇短切片；每组预置一个目标和一次明确标记为演示的修改稿核查。新任务最初待核查。它们不是完整 IELTS 作文、评分范文或真实学生档案。载入前预览，重复载入跳过已有作文；若用户修改过同 ID 的教学判断，再载入会保留另一版本，需人工核对。

## 失败与边界

学生编号是本地分组，不是登录账户或权限边界。正文和教学记录仍只存于该浏览器地址；无云同步、自动草稿保存或班级平台集成。TXT 一批最多 50 份、共 3 MB；JSON 备份上限 10 MB，浏览器存储容量可能更小。批量导入不会猜测学生、日期或修改关系。人工核查与反馈单都不能证明因果学习效果。词形归并仍是轻量规则，没有上下文词性、词义判断或 AI 生成建议。

## 验证与后续证据

71 项自动测试、类型检查通过；生产构建与浏览器证据见[走查记录](./USABILITY_REVIEW_CN.md)。浏览器实际检查三组材料、保存判断与新任务证据、修改稿对照、下载反馈单和窄屏。未来有参与者后，优先记录材料准备与核查总时间、学生能否解释修改、下一次是否主动使用，以及新任务中的表达适切性。当前不报告满意度、效率提升或提分。
