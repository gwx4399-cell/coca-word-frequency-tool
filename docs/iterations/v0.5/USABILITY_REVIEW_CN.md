# v0.5 模拟走查与验证记录

日期：2026-11-03 至 2026-11-04（Asia/Taipei）。分支实现，关联[草稿 PR #10](https://github.com/gwx4399-cell/coca-word-frequency-tool/pull/10)；未合并、未发布。

## 方法

同一个代理检查三个假设学习阶段和教师操作。应用内九篇虚构短切片、目标与预置核查来自 `src/teaching/demo.ts`。不是完整 IELTS 答卷，没有人类评分、教师参与、访谈、真实使用时长或学习效果测量。演示材料不会在首次打开页面时自动写入。

自动检查与实际浏览器走查分开记录。自动检查覆盖完整新建目标、修改稿、核查、导入及失败路径；浏览器实际操作用于核查可见交互、分组和布局。不会把预置的演示判断算作观察所得的学习效果。

## 实际浏览器操作

| 场景 | 操作与结果 |
| --- | --- |
| 首次使用 | 打开本地独立地址，预览三组材料，看到新增 9 篇、3 条判断；确认后进入学习目标，按学生选择。 |
| 基础练习 | 查看 good 具体化目标和修改稿证据；选择公共公园新任务，选择原句、填写理由和反思，人工保存“新任务中有恰当使用的证据”。 |
| 表达拓展 | 切换学生后不显示基础组核查；从目标进入公共交通修改稿，展开原稿与当前稿对照。实际下载反馈单并在浏览器查看，其内容包含原稿目标、修改稿原句、依据和反思。 |
| 语义与语气 | 查看有限样本与结论范围目标，核查博物馆新任务并保存具体原句；回到原稿，给 statistically significant 所在句增加“保留”判断，说明专业含义不应机械替换。 |
| 窄屏 | 以 390×844 视口检查目标、长原句、反思和按钮；DOM 内容宽度与可用宽度均为 375px，没有页面横向溢出。此为桌面浏览器视口模拟，不是手机硬件测试。完成后恢复视口。 |

## 走查带来的修正

- 修改稿详情增加当前学生的活跃目标和进入核查的入口，减少回忆原目标的负担。
- 从修改稿导出反馈单时包含整个任务族的教学判断，避免原稿有目标而修改稿导出空白。
- “Original essay”改为“当前稿件原文”，避免把修改稿误称为原稿。
- 导入的原稿可由教师明确调整为独立任务；已有关系不允许被不一致的更改破坏。
- 缩短主标题并调整窄屏排版，让目标入口更容易到达。

## 自动与构建验证

71 项测试、13 文件通过；类型检查通过；生产构建通过，保留已有的大词表包体提示。新增重要场景包括：不同学生相同标题与正文不合并；原稿/修改稿只取一份；旧数据不自动归组；伪造引文、错误学生、悬空引用与循环引用整批拒绝；备份 ID 冲突后仍能找回父稿和核查；冲突教学判断保留；存储满时不丢原值；“没有适用机会”重载后仍保留且不变为掌握；TXT 多文件先预览再整体导入；反馈单正确转义 HTML。

电脑默认 Node 版本曾与浏览器模拟环境的 localStorage 冲突，现已显式绑定 jsdom 的存储；最终验证使用项目 CI 同版本的 Node 22。此前的临时失败不作为产品数据丢失记录。
