# DEEA v0.2 产品需求文档（中文）

**状态**：已在 [PR #4](https://github.com/gwx4399-cell/coca-word-frequency-tool/pull/4) 的草稿分支实现；尚未合并至 `main`。  
**日期**：2026-09-23。**版本主题**：三篇作文后的写作建议与低负担分析。  
**产品定位**：浏览器端英语写作练习原型；当前建议来自固定规则与人工撰写的提示，**未接入 AI 模型**。

## 1. 问题和这次迭代的来源

目标用户在现有原型中看到 lexical tokens、unique analyzed lemmas、COCA coverage、每百词出现率、派生 lemma 排名与语料频数，却很难据此决定下一篇作文该练什么。分析和保存分为两步；存满三篇后没有写作建议；相同标题可以重复出现。用户明确认可 observed forms，因为它能将 `important` 与 `Important` 等原文形式对应起来。

本次目标是让**提交一篇作文**与**看到下一步练习方向**构成可用的最小闭环：输入 → 分析并保存 → 累积三篇 → 查看带逐篇证据的提示 → 回看原文。它不承担写作评分、语义准确性判断或“词越难越好”的建议。

## 2. 用户、场景与核心决策

首版针对一个浏览器中的一名写作者；学习者可自己查看建议，教师可与学习者一起复核语境。不支持班级、账号或多人的数据隔离。演示时应使用同文体议论文，**当前代码尚无文体字段，也不会自动阻止不同文体混比**。

| 用户反馈 | v0.2 决策 | 理由 |
| --- | --- | --- |
| 统计项过多 | 界面只保留总词数、lemma、observed forms 和本篇出现次数。 | 直接回答“写了什么、用了几次”；COCA 数据仍可供内部筛选。 |
| 三篇后应有建议 | 最新三篇已保存作文构成滚动观察窗口，第三篇保存后立即出现“Writing advice / 写作建议”。 | 尽早让用户看到数据与行动的联系；三篇是 Demo 触发条件，非被证实的学习阈值。 |
| 分析后自动保存 | 将 Analyze 和 Save 合为一个动作；成功与失败都有反馈。 | 减少遗漏保存，也使第三篇后的提示按真实历史更新。 |
| 标题不应重复 | 不同作文标题忽略首尾空格和大小写后必须唯一；完全相同的记录重复分析不新增。 | 历史列表更易识别；不破坏已有记录。 |
| observed forms 有用 | 保留原文词形列。 | 为用户回查原句提供可解释的线索。 |

| 功能 | 实际行为 | 验收证据 |

## 4. 页面和交互

**New essay** 保留标题、写作日期、可选题目和正文。按钮为 `Analyze and save`；分析结果在本页展开。**History** 保留日期排序、原文、单篇分析与确认删除。建议面板位于两张视图的共同导航下，因而第三篇写完后无需去另一个页面找；已有三篇浏览器记录的用户刷新后也能看到。

建议面板有三种状态：

1. **重复表达候选**：下述人工示例词中，某词至少在一篇出现三次且在最近三篇中的至少两篇出现。展示最多三个词、逐篇证据和人工撰写的意义区别练习。
2. **值得继续观察**：没有符合前项条件的词，但示例词在至少两篇出现。提示复现证据，不称其为依赖。
3. **一般练习提示**：示例词无跨篇复现。建议用户选择一处评价性表达，把含义写具体，再检查准确性；不伪造个性化发现。

**示例**：最近三篇中，作文 A 的 `important` 出现 3 次，B 出现 2 次，C 未出现。面板显示“2/3 篇，共 5 次”，列出 A/B 的次数，并提示区分“影响显著”与“不可缺少”。这只是需要回看原句的候选；如果 B 的 `important` 指不同语义功能，教师应否定“依赖”的推断。

不足三篇时不显示面板。删除作文后重新从当前历史计算；若少于三篇，面板消失。标题冲突时保持编辑内容，提示另起标题。完全相同的作文再次分析，历史数量不增加。若浏览器存储失败，分析可显示，但错误明确说明作文未保存。

## 5. 规则边界与教学解释

示例名单为 `important`、`good`、`bad`、`big`、`serious`、`useful`、`effective`、`different`，且词必须命中当前 COCA 派生词表。程序按 lemma 计数，没有逐次词性标注；例如同形词可能并非形容词。替代表达仅作为核对意义的练习选项，**不能自动替换**。作文题目可能要求反复提及同一个概念，复现次数本身不证明问题。

当前的“三篇建议”只观察最近三篇作文，与规划中的“目标建立后 +1/+3/+5 篇观察维持和回归”是两种不同功能。后者、同语义功能占比 >50%、AWL/UWL、多文体基线与自动 AI 建议均未实现；详见 [v0.1 产品方向](../../DEEA_PRD_CN.md)。

## 6. 成功判断与后续验证

**已验证的是软件行为**：本地测试、类型检查与构建均通过；不能据此声称学习效果。下一轮应让学习者和教师用同文体真实样例走查：是否看懂逐篇证据，建议词是否真的承担同一种语义功能，给出的替代表达是否准确，是否愿意在下一篇主动尝试。可以记录能否完成“查看建议 → 回看原文 → 制定一个可操作练习”及其原因；不以 COCA coverage 或低频词数量评价学习者。

## 7. 范围外与风险

- 无账号、后端、导出或同步；历史仅在当前浏览器的 `localStorage`，清除数据会丢失作文。
- 未做自动词性识别、语义组机会分母、正式词汇拓展目标、长期状态、AI API 或人工教师审核流程。
- 已有历史中的同名作文不会自动删除；规则只阻止新增不同作文的重复标题。
- 仅测试了规定的功能行为；仍需用真实作文和用户访谈验证教学价值。
