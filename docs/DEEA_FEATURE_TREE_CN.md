# DEEA Feature Tree v0.1

状态：产品设计草案｜2026-09-23

本文件按**产品模块 → 用户功能**组织。页面单列在“页面映射”；数据与算法能力单列在后表，避免把一个计算步骤误作一张页面。标记：`已有`、`调整`、`新增`、`后续`。

## 产品模块与功能

| 产品模块 | 用户功能 | 阶段 | 用户可见结果 |
| --- | --- | --- | --- |
| 作文管理 | 新建议论文：标题、日期、题目、正文，分析后保存 | 调整 | 保留原有输入区；明确 Demo 只比较议论文。 |
| 作文管理 | 历史列表、原文、单篇分析、确认后删除 | 已有 | 可从结果回查原文；旧记录需人工确定是否纳入议论文比较。 |
| 单篇分析 | 基础字数、词形与 lemma 明细 | 已有 | 放进“详细数据”，解释 COCA coverage 是词表覆盖，不是写作分数。 |
| 单篇分析 | 显示少量重复形容词候选及原文依据 | 新增 | 候选仅提示核查；可查看出现次数、语境和 COCA 搜索范围。 |
| 长期追踪 | 查看每个词跨篇的出现篇数、次数、连续情况和序列 | 新增 | 看到词是否重复出现；不同议论文题目可能影响机会。 |
| 长期追踪 | 在核查后的示例组内查看集中度 | 新增 | 有足够人工标注时展示“同组机会中的占比”；否则标未评估。 |
| 词汇目标 | 从候选设目标，写教学提示/适用语境/替代表达 | 新增 | 学习者知道下阶段练什么；教师可编辑建议。 |
| 词汇目标 | 查看开始时间、关联作文与当前观察状态 | 新增 | 状态有可追溯的作文证据。 |
| 后续观察 | 目标后 +1、+3、+5 篇检查 | 新增 | 分别显示即时响应、初步维持、持续趋势；样本不够等待。 |
| 成长总览 | 当前目标、最近发现、改善与可能回归的证据卡 | 新增 | 从 Growth 快速进入目标与原文。 |
| 用户管理 | 多作者、角色权限、班级与跨设备同步 | 后续 | 不进入单人浏览器 Demo。 |
| 语言分析 | 自动词性判别、完整语义组、AWL/UWL、AI 建议 | 后续 | Demo 仅预留接口与示例配置。 |

## 页面映射（页面不是功能树的层级）

| 页面 / 视图 | 承载哪些功能 | 独立页面？ |
| --- | --- | --- |
| Growth（首页） | 目标概览、证据摘要、空状态和“写新作文”入口 | 是 |
| New essay | 输入、分析、保存、单篇候选 | 是；保留现有工作区 |
| Essay detail | 原文、单篇分析、候选证据；由历史或 Growth 打开 | 是（可用应用内视图实现） |
| History | 日期列表、原文入口、删除、是否参与比较 | 是 |
| Target detail | 目标说明、候选证据、按篇时间序列、+1/+3/+5 观察 | 是（可先用应用内视图实现） |
| Detailed data | 完整 lemma 表和 COCA 来源说明 | 单篇结果中的可展开区域 |

## 数据与算法能力（界面背后的支持）

| 能力 | 输入 → 输出 | 边界 |
| --- | --- | --- |
| 文本与 COCA 分析 | 原文 + 本地词表 → token、lemma、次数、派生 rank | 已有；词形还原是确定性启发式，COCA 多词性 lemma 聚合。 |
| 候选筛选 | lemma 次数 + 小型人工形容词名单 + COCA 命中 → 待核查词 | ≥3 次只触发观察；无法逐 token 判断词性。 |
| 语义机会标注 | 原文片段 + 人工示例组判断 → 分子/分母 | 分母未知不计算 >50%；若有歧义则需人工复核。 |
| 同文体序列 | 纳入的议论文 + 同一浏览器作者 + 稳定排序 → 有序作文 | 历史旧记录须明确纳入；不能把不同文体混比。 |
| 跨篇聚合 | 序列 + lemma → 出现篇数、总次数、连续篇数 | 同题/异题机会不同，数量不等于质量变化。 |
| 目标持久化 | 词、示例组、教学目标、锚点作文 ID → 本地目标 | 人工教学说明与分析结果分开保存；删除锚点需提示并处理。 |
| 观察窗口 | 锚点后合格作文 → +1/+3/+5 证据 | 产品假设；“改善”“回归”需有机会与语境证据，不凭次数自动定性。 |
| 本地存储 | 作文 + 目标 + 记录版本 → `localStorage` | 无账号、跨设备或服务器埋点；浏览器清理即丢失。 |

## MVP 切片顺序

1. 使议论文范围、旧记录纳入规则与单篇候选证据成立。
2. 展示跨篇复现和 Growth 摘要，并连回作文原文。
3. 增加人工目标、后续作文窗口与谨慎的状态文字。
4. 用少量示例组验证集中度；其余语义功能待后续。
